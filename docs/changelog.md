| (stable element ids) | **Stable, never-reused element identity; ABA-proof ticking; a sync skip that sees writes which bypass the change count.** Every `ScriptObject` gets a unique 64-bit id at construction (`objectId()`, a monotonic count, never reused). An element's ImGui ID scope and its layout cache key are made from its instance's id instead of its table's address (`Renderer::Types::elementId`, `Renderer::elementId`/`elementImGuiId`/`pushElementId`, `Frame::Child::id()`, new `Frame::Child::pushId()` used by `TabBar` for its pages), so a table that Lua allocates at a collected one's address no longer inherits its cached size (misplaced for a frame) or its ImGui state (open trees, scroll positions, text edits); an element whose constructor threw isn't rendered. | (font outlines) | **`checkFont` checks TrueType outlines and what ImGui does with a glyph's box; the `font` fuzz target rasterizes.** stb_truetype decodes a glyph's `glyf` outline without bounds checks when ImGui rasterizes it, so a font that passed `checkFont` with a damaged outline could crash the app the first time it drew the glyph. `checkFont` now decodes every glyph's outline the way `stbtt_GetGlyphShape` does (new class `Outlines` in `imlui.theme.font_check`, a structural mirror: stb_truetype reads glyph data through raw pointers, so it can't be run under a bounds-checking reader like the CFF charstrings): simple glyphs (end points, instruction length, flags with repeats, 1- or 2-byte coordinates, all inside the glyph; in a glyph that can be drawn, no last contour of one point off the curve, which makes stb_truetype read a vertex past its array; Calibri and Consolas have such placeholders with an empty box, which ImGui never draws) and composite glyphs (each part's flags, offset and scale inside the glyph; no part placed by matching points, an `STBTT_assert`; no part containing the glyph itself, a stack overflow; at most 16 levels of nesting, 2^18 vertices and a bounded amount of copying per glyph; transformed coordinates within 16 bits, as stb_truetype converts them from float to `short`). Tests: `FontCheck.GlyphOutlinesAreReadLikeStbTruetype` (crafted glyphs: flags, repeats, coordinates, instructions and end points running past the glyph, a lone off-curve last contour drawn, as a placeholder and inside a composite, scale variants, cut-short parts, parts by points, self-containing parts, 16/17 nesting levels, exploding repeats, parts moved out of range, inverted and oversized boxes, outlines and curves rising above a below-baseline box, directly and through a composite); in `RejectsDamagedFonts` a damaged Roboto outline, a zero, negative and 1-unit `hhea` height (TrueType and CFF); new fuzz corpus files `tiny_glyf.ttf` and `regress-glyf-*` / `regress-hhea-negative-height.ttf` (composite cycle, nesting, flags/coordinates overrun, lone off-curve contour, part out of range, `loca` past `glyf`, outline rising above its box, negative height). Docs: [Architecture](architecture.md), [Development](development.md#fuzzing). |

| (Lua as C++) | **Lua is compiled as C++: a Lua error is a C++ exception, not a `longjmp`.** The vendored Lua builds as one C++ translation unit (`external/lua_cxx/imlui_lua.cpp` includes Lua's `onelua.c`; the sources are unchanged) that sets `LUAI_THROW`/`LUAI_TRY`: Lua throws `imlui_lua_error` (`lua::Raised` in the wrapper), and a `std::bad_alloc` reaching a protected call becomes a Lua memory error. The C++ frames a Lua error unwinds now run their destructors, so C++ objects alive at a raise (or a raise inside a catch block) are no longer undefined behaviour.
