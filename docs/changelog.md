| (port prep) | **Preparing the typed port of the built-ins.** `imlui::Object` is now `imlui::ScriptObject` (module `imlui.types.script_object`): the base of anything a Lua script can see. `Frame` covers everything the built-in handlers use: `Frame::Child` handles from `forEachChild` (visible children only; `render`, `isVisual`, `node`, `type`, `id`, `lastWidth`/`lastHeight` from the last frame, `as<T>()` with the child's properties synced first), `renderChildren(node)`/`renderStack(node)` for another element's children, `withElementProp`/`renderElementProp` for element-valued props, `attachMenu`, `setWindowTitle`, `size(key, ifAuto)`, `labelId`, `alignFactor`. `TypeBuilder::extends<Base>()` lets a subclass's `declare` extend its base's; a subclass without its own `declare` no longer compiles (it would have lost its members). Aliases (one class under several names) are tested. The navigation context is the shared module `imlui.ui.navigation_scope` (`NavigationScope`). Every element group module has a `register<Group>Types(TypeRegistry&)`, called by `registerBuiltinTypes` after the handlers (`ProgressBar` in `registerDataTypes`, `Timer` in `registerSystemTypes`); a type replaces a handler of the same name. Guide: [Porting a built-in to the typed API](development.md#porting-a-built-in-to-the-typed-api). Headless-frame tests for `Frame` (`frame_test.cpp`). |
| (types) | **QML-style C++ type registration.** New `imlui.types.*` modules: `Object` (base of everything exposed to Lua: a weak Lua link; `notify(property)` writes the value back through `Node::set`, emits `on<Name>Changed` and requests a frame; `emit(signal, args...)`), `Element` (`render(Frame&)`, `componentComplete()`, `destroyed()`), `Frame` (render context: children, `dp`, draw list, frame requests, theme, the `Node`), `TypeBuilder<T>` (`property` read/write and read-only, `signal`, `method` with argument and result conversion, `nonVisual`, `defaultProperty`), `LuaConvert<T>` (bool, arithmetic, strings, `Color`, `optional`, `vector`; user-specializable), `TypeInfo` and `TypeRegistry` (installs types and singletons into every Lua state, so hot reload keeps working). `Engine::registerType<T>(name)`, `Engine::registerSingleton(name, obj)`, `Engine::types()`, and the thread-safe `Engine::post(fn)`. DSL constructors of registered types create the C++ instance at once (a `__native` userdata with `__gc`; the element table gets a metatable for `el:method()`). Declared properties are synced into setters before each render, only on change. `ui.types()` lists the types. Singletons are globals with property and method `__index`, setter `__newindex` and assignable `on*` handlers. `ProgressBar` and `Timer` are ported to the typed API, with the same props and signals. New example executable `imlui_custom_types` (`examples/custom_types/`: a Material arc `Gauge` element and a `SystemInfo` singleton fed by a worker thread). `defaultConfig` takes a default script name. `Node::setTop`. New guide: [Registering C++ types](extending.md). Tests for conversion, dispatch, sync, `notify`/`emit`, lifetime, singletons and reinstalling. |
| (adaptive) | **Adaptive layouts.** Material 3 window size classes: `ui.windowSize()` (dp, so zoom counts), `ui.sizeClass()` (`compact` < 600, `medium` < 840, `expanded` < 1200, `large` < 1600, `extraLarge`), `ui.sizeClassFor(w)`, and `ui.setWindowSize(w, h)` in dp (a new `NativeHooks::setWindowSize`, applied after the frame). The classification is the pure `imlui.ui.size_class` module. `Responsive { compact = ..., medium = ..., expanded = ... }` is an inline container that shows the element for the current class, falling back to the nearest smaller one given (`false` shows nothing). New elements: `NavigationBar` (80dp bottom bar, destinations share the width), `NavigationRail` (80dp rail with an optional `header`) and `ModalNavigationDrawer` (scrim plus a sheet that slides in from the left in its own window above the app; scrim click and Escape close it, `open` is two-way, `onClosed`). `NavigationItem` draws as a bar or rail destination inside those containers (a scoped navigation context set by the container), with a badge on the icon. New widgets `md::navigationBarItem`, `md::navigationRailItem` and `imlui.widgets.navigation_drawer`. The gallery adapts: a modal drawer from the top app bar on compact windows, a rail on medium ones, the standard drawer from expanded up; padding and grid columns follow the width, and the overflow menu toggles a phone preview. Tests for the size class boundaries and `Responsive`'s selection. |
| (shapes) | **Crisp Material shapes.** New shape helpers in `imlui.widgets.common` (`fillRoundRect`, `strokeRoundRect`, `fillCircle`, `strokeCircle`, `strokeArc`, `hLine`, `vLine`) replace ImGui's `AddRect*`/`AddCircle*` in every widget. They use the true corner radius (ImGui clamps it to `min(w, h)/2 - 1`, so pills had flat ends), tessellate arcs by length (about one segment per 2px), snap rects to whole pixels and keep strokes whole-pixel wide and inside the shape, so 1dp outlines are single crisp pixels. Buttons, chips, segmented buttons, the switch track, linear progress and the slider track are now exact pills. The unchecked checkbox outline is now inside its 18dp box (it was 20dp wide, so the box changed size when checked). `textTop()` centers text on the cap height and rounds to a whole pixel; `drawTextV` and the buttons, chips, segmented buttons, tabs and bubbles use it (labels sat about 1px low). The theme sets `CircleTessellationMaxError = 0.10` for smoother ImGui-drawn roundings (cards, popups, scrollbars). The Slider's `format` is validated (`isValidFloatFormat` in the new `imlui.widgets.value_format`: one `%f`/`%e`/`%g` conversion, `%%` allowed). An invalid one falls back to `"%.2f"` and is logged once, instead of reaching `snprintf` unchecked. |
| (warnings) | **Zero-warning policy.** Our targets (`imlui`, `imlui_app`, `imlui_tests`) build with a strict clang warning set (`-Wall -Wextra -Wpedantic -Wshadow -Wconversion -Wsign-conversion -Wold-style-cast`, and more, in `cmake/ImluiWarnings.cmake`) as errors. Vendored targets are `SYSTEM`, so their headers don't trigger our warnings, and keep their own flags. Fixed the existing warnings (float-to-double promotions when pushing numbers to Lua, signed container indices). New `clang-asan` preset: ASan + UBSan on every target, vendored included. Debug builds of our targets trap on signed overflow (`-ftrapv`). The policy is in [CODE_STYLE.md](../CODE_STYLE.md#warnings-and-compiler-checks), the commands in [Development](development.md#building-and-testing). |

Idle CPU on a static gallery page dropped from a full core to almost nothing. New module `imlui.ui.frame_request`. The gallery gets a UI zoom slider. |

**Feature summary:**

- A declarative Lua UI with plain, binding and two-way property values, `on*` signals, ids, observable `state`
  with `watch`, `Repeater`/`ListView`/`If`/`Loader`/`Responsive`, and file-based components through `require`.
- Adaptive layouts from Material 3 window size classes, with navigation bars, rails and a modal drawer.
- 58 built-in element types covering windows, layout, app bars and navigation, menus, text, controls, inputs,
  feedback, charts, tables and Canvas.
- QML-style C++ extension: element types and singletons registered from C++ with declared properties, signals and
  methods ([Registering C++ types](extending.md)).
- A Material 3 theme generated from a seed in OKLCH, with role/ImGui/style overrides and ImGui presets, decided
  entirely in Lua and applied between frames.
- Hot reload of any `.lua` file, an in-app error overlay, logging through spdlog, and live redraw during resize.
